STACKS CHANGELOG
================

Versioning: x.0.0 = major (new features) | 1.x.0 = minor (small additions/changes, batched) | 1.0.x = patch (tiny fixes/tweaks)


6.4.0 -- 2026-09-17
--------------------
- Added free-text notes to each copy, styled as a manila notecard (tape strip, slight
  tilt, folded corner) rather than a plain form field -- for things like "recommended by
  the Sorensens" or "read this before lending it out again." Notes are per physical copy,
  not per book title, since two copies of the same ISBN in one library can carry
  different notes. The database field and its PATCH endpoint already existed (added
  earlier for CSV round-tripping but never surfaced in the UI); this was mostly wiring up
  the UI plus a small amount of new client state.
- The book detail page shows the card directly (add/edit/delete inline, with an
  auto-growing textarea so editing never requires scrolling to see the whole note). The
  Library page's grid and list views show a small manila tag in the corner of a copy's
  cover when it has a note -- clicking the tag opens a lighter read/edit popup in place,
  without navigating to the book page or disturbing the row's existing reserve/remove
  buttons. Mocked up first as an Artifact, four rounds of feedback before building: the
  grid tag originally opened the full book page (changed to a dedicated popup); the list
  view's note affordance first lived in the row's actions cluster, which threw off icon
  alignment row-to-row once notes made the icon count inconsistent (moved to the cover
  corner, matching the grid tile, so actions stay in the same two spots on every row);
  and the popup itself gained inline editing and the same tape/folded-corner treatment as
  the on-page card after the first pass only supported reading.
- Also touched globals.css's dark-mode handling from a concurrent PR (#16, the theme
  switcher) landing at the same time: the new manila color tokens now need to be defined
  in both dark-mode paths that PR introduced (`@media (prefers-color-scheme: dark)` for
  the OS-follows-system case and the new `:root[data-theme="dark"]` block for an explicit
  choice), not just one, or an explicitly-dark session would render notecards with
  undefined colors.


6.3.0 -- 2026-09-17
--------------------
- Added a Light / Dark / System theme switcher to Settings, so the app no longer
  has to follow the OS preference. Choice is stored per browser (localStorage),
  not per account -- deliberate, since it's a device-level display preference and
  keeping it there avoids a schema change and lets a shared device revert with
  no account switching. A blocking inline script in the root layout applies a
  stored choice before first paint, so there's no flash of the wrong theme on
  load.
- This needed touching how dark mode itself works, not just adding a toggle:
  the existing `@media (prefers-color-scheme: dark)` block in globals.css only
  ever reflected the OS, with no way to override it. It's now guarded so an
  explicit choice wins -- a `data-theme="light"|"dark"` attribute on <html>
  (absent for "System") -- with the same dark variable set duplicated under a
  new `:root[data-theme="dark"]` block for the explicit-dark case. Tailwind's
  own `dark:` variant (used in one place, book-cover.tsx, to swap which token
  a border/background uses rather than just riding a token's own light/dark
  value) defaults to OS-only in Tailwind v4 regardless of this, so it's now
  redefined via `@custom-variant dark` to also honor `data-theme`, or it would
  have silently ignored an explicit choice.


6.2.0 -- 2026-09-16
--------------------
- Added a real progress indicator to the import loading screen: a determinate progress
  bar, a "Row X of Y" counter with percentage, a ticker naming the book currently being
  processed, and a live New/Updated/Skipped tally that updates as it goes -- so a large
  import (hundreds of rows) reads as visibly working the whole way through, not just a
  static "Importing..." label for however long it takes. Mocked up first as an Artifact
  over a couple of rounds before building.
- This required changing how import actually runs, not just the UI: previously the whole
  file was sent as one request that only replied once every row was done, which had two
  problems -- no way to show real progress mid-request, and (worse) a real risk of the
  whole thing rolling back or dying if the connection dropped before that one giant
  response ever came back. Now the client splits the file into batches of 10 rows and
  sends them one at a time, each one committing fully before the next is sent, so closing
  the tab mid-import only loses whatever hasn't been sent yet -- everything already
  processed stays saved. If a batch request fails outright, the confirm screen reports
  exactly how many of the file's rows made it in before stopping, since by then some
  already have -- re-running the same file is safe and picks up the rest (Copy-ID-matched
  rows just re-match harmlessly).
- The progress bar/ticker still read as continuously moving even though the batches
  arrive in chunks: each batch's rows are revealed to the UI one at a time at a pace that
  adapts to how long that batch actually took, rather than jumping straight to the new
  totals the instant a batch's response lands. The import endpoint now returns a
  per-row outcome list (not just aggregate counts) specifically so the client has real
  data to animate through, rather than faking movement.


6.1.0 -- 2026-09-16
--------------------
- Added an animated loading state to the import confirm modal, shown while the actual
  import request is in flight: the three bars of the Mark logo drop into place bottom-to-
  top like books settling onto a shelf, then lift away and repeat (pure CSS keyframes,
  respects prefers-reduced-motion). Mocked up first in a Claude Design canvas -- two
  motion directions were drafted (bars dropping in vertically vs. sliding in from
  alternating sides) before picking the dropping version.
- Fixed the Settings page's "Last backup taken by..." line not updating until the page
  was manually refreshed. Root cause: the download button triggered the export via a
  plain `<a>` click (fire-and-forget, no way to know when the request actually finished)
  and just guessed an 800ms delay before calling `router.refresh()` -- under real
  conditions the refresh could fire before the server's `Library.lastBackupAt` write had
  actually completed, so the page re-rendered with stale data. Fixed by fetching the
  export directly (so the response is awaited, by which point the write has definitely
  landed), reading the new date/name back from response headers the export route now
  sets, and updating the displayed text from that immediately -- no more guessing a
  timeout, and no dependency on a full router refresh's timing at all.


6.0.0 -- 2026-09-15
--------------------
- Added CSV backup and import to Settings, in a new "Backup & Import" block. Mocked up first
  as an interactive Artifact over several rounds before any code was written -- see that
  session's design decisions below, since most of this feature's behavior was worked out
  there rather than while building.
- Backup: a "Download CSV backup" button exports every non-removed copy (Copy ID, ISBN,
  effective title/authors/publisher, shelf, status, reservation, notes, BookCrossing ID,
  date added) using the library's override-merged view (applyBookOverride), so a backup
  reflects what the library actually sees, not just the shared Book row. Records who took
  the backup and when (Library.lastBackupAt/lastBackupByUserId) and shows it above the
  button. A separate "Download import template" link produces the same file shape with zero
  data rows -- literally what a real export produces for an empty library.
- Import: drag-and-drop or file-picker CSV upload, parsed and column-mapped entirely in the
  browser (src/lib/csv.ts's isomorphic parseCsv) before anything reaches the server. The
  mapping screen auto-matches columns by name, lets any column be manually remapped or
  ignored via a dropdown in its header, and disables a target field in every other column's
  dropdown once one column claims it -- so the same field can never be mapped twice, a bug
  caught during the mockup round rather than in production.
- Import matches rows to existing copies by Copy ID (from a prior export), not ISBN --
  ISBN alone can't tell two physical copies of the same book apart. A row with no Copy ID,
  or one this library doesn't recognize, always creates a new copy rather than merging into
  an existing one; a matched row only touches the fields it actually supplies, leaving
  everything else on that copy untouched (real upsert semantics, not a blind overwrite).
  Every ISBN is validated with the same cleanIsbn/isValidIsbn rules scan-in already uses;
  rows with a missing or malformed ISBN are skipped and reported as separate counts on the
  confirm screen, which now runs a real dry-run against the database (a `dryRun` mode on
  POST /api/library/import that does the same Copy ID/ISBN checks with zero writes) so the
  new/updated/skipped counts shown before committing are exactly what the real import will
  do, not an estimate.
- A brand-new ISBN encountered during import never triggers a live Google Books/Open
  Library lookup -- that's the same external-call path that already caused a production
  timeout once for a single scan-in, and an import can easily contain dozens of new ISBNs.
  Instead it gets a bare Book placeholder marked "manual-unresolved" (reusing scan-in's own
  failed-lookup marker), which scan-in already retries automatically the next time that
  ISBN is scanned in anywhere. Any book-content fields (title/authors/publisher) a row
  supplies are written as this library's BookOverride, never onto the shared Book row --
  so importing bad or guessed data into one library can't corrupt what another library
  sharing that ISBN sees, the same protection the manual book-edit form already has.
- Added a "Look up this ISBN" button to the book-edit page for any book still marked
  manual-unresolved, capped at one manual attempt per copy (Book.manualLookupAttempts) so
  it can't be spammed on a book that genuinely isn't in either catalog -- but this cap is
  completely separate from, and doesn't limit, scan-in's own automatic retry, since that
  only ever fires once per real physical scan and the catalogs it checks keep growing. A
  successful lookup -- whether a real catalog hit or one already resolved a moment earlier
  by a different copy of the same book, which skips the network call entirely -- always
  wins over whatever was on the page and is written straight to the database immediately,
  with no separate save step, so nothing is lost if the page is closed without saving. It
  also deletes this library's existing BookOverride for that book rather than leaving it in
  place: an override otherwise always wins over the canonical Book in the merged view, which
  would make the button look like it does nothing if a library had already saved its own
  correction for a still-unidentified book.


5.2.1 -- 2026-09-15
--------------------
- Fixed the invite flow losing the invite code when switching from sign-in to sign-up. The invite page's "Sign in" link correctly carries the code via `?next=/join/{code}`, but the sign-in page's "no account yet?" link was a bare `/register` with no invite param, so someone who clicked "Sign in" by mistake and then tried to create an account instead landed on the generic "create a new library" flow rather than joining the library they were actually invited to. Fixed by having the login page read `next` (via the `use()` hook, per the Next 16 searchParams gotcha, not `window.location.search`), recovering the invite code from it, and passing it through to the register link. Also renamed that link's text from "Create a library" to "Sign up," since it no longer always means creating a brand-new library.


5.2.0 -- 2026-09-15
--------------------
- The book-edit form now previews the cover image next to the URL field before you save: it shows the currently-saved cover on load, and a "Refresh" button re-attempts loading whatever's currently typed in the field, without saving anything. Built by reusing the existing BookCover component (same fallback plate as everywhere else in the app) keyed on the URL-plus-attempt-count, so each click forces a real remount and a fresh load attempt rather than getting stuck on a stale failure state. 5.1.0 -- 2026-09-14
--------------------
- Added a "BookCrossing ID" (BCID) field, shown under the ISBN below the cover on the book detail page, and searchable -- the Library search bar now reads "Search by title, author, ISBN, or BCID". It lives on `Copy`, not `Book`: a BCID identifies one physical released copy, not a title/edition, so two copies of the same ISBN (even within the same library) can have different BCIDs.
- Added an editable version of the book detail page (/dashboard/copies/[id]/edit) reachable via a new "Edit details" button both on the book detail page itself and directly from the scan-in success banner. Lets you correct title, authors, publisher, page count, cover URL, description, and BCID.
- These corrections are library-scoped, not global: `Book` rows are a shared catalog keyed by ISBN (see CLAUDE.md) so every library reuses the same row and the same ISBN-lookup data, but edits are stored separately as a `BookOverride` per (book, library) pair and merged over the canonical fields only for the library that made them. One library's bad edit is invisible to every other library sharing that ISBN -- important given anyone can register and create their own library here, so "shared catalog" originally meant user edits would have been shared with total strangers too. Backed by `PATCH /api/copies/[id]/book`, open to any signed-in member of a library holding a copy (not owner/admin-gated) since a correction now only affects that member's own library.
- Replaced the old "Added, but couldn't find book details -- edit the title later." scan-in message, which had no actual path to editing, with "Added, but couldn't find book details." plus a real "Edit details" button that goes straight to the new edit form.

5.0.0 -- 2026-09-14
--------------------
- Replaced the unmodified Next.js starter look (flat white/black, Geist-falling-back-to-Arial, default favicon, no logo) with a full visual identity, direction "Ex Libris": an archival/manila palette (paper surfaces, ink text, a stamp-red accent, a teal secondary) with first-class light and dark variants -- neither is a mechanical inversion of the other, since Stacks' dark mode is driven purely by `prefers-color-scheme` with no in-app toggle yet. Typography is a three-way pairing: Newsreader (display/titles, book titles, stat numbers), Karla (interface/body), and IBM Plex Mono (labels, dates, ISBNs, shelf codes, status pills), all self-hosted via `next/font/google`. Sharp corners everywhere (2px radius) and a flat "stacked paper" box-shadow (no blur) on cards and stat tiles are the direction's signature.
- Added a mark (three offset rounded bars reading as a leaning stack of spines) as the app's logo, used in the landing/dashboard headers, and regenerated the favicon (`favicon.ico`, `icon.svg`, `apple-icon.png`) from it -- previously the default Next.js/Vercel icon. Removed the unused Next.js starter SVGs (`next.svg`, `vercel.svg`, `globe.svg`, `file.svg`, `window.svg`) from `/public`.
- Restyled every page and component to the new tokens/typography: landing, sign in, register/invite, dashboard chrome (header, library switcher, nav tabs), overview stats, the Library list and grid views, book detail, the reservation and delete-confirmation modals, shelves, reservations, settings, and scan. No behavior changed -- same routes, same fetches, same `localStorage`-backed view-mode persistence, same bulk-select/right-click/reservation flows throughout.
- The landing page's footer stats ("N books / N shelves / N reserved") are now wired to real counts across all libraries via a server-side query, instead of being static/absent.
- Added `src/lib/form-styles.ts` to share the underline-input/mono-label treatment used by every form across the app (auth, reservation, shelves, settings) instead of repeating the same Tailwind classes in each one.


4.0.0 -- 2026-09-14
--------------------
- The Library page now has a list/grid view toggle (remembered per browser). List view is a sortable table -- click any column header (Title, Author, Shelf, Date added, Status) to sort by it, click again to reverse. Grid view shows cover-forward cards with a checkbox that appears on hover.
- Clicking a book (a row, or a cover in grid view) now opens a full detail page with a larger cover, publisher/page-count facts, the description, and Reserve/Remove actions, instead of nothing -- there was previously no way to see a single book's full information.
- Each row/card now has its own reserve and delete icon buttons, plus checkboxes for multi-select with a bulk action bar (Reserve, Edit reservations, Delete) once anything's selected, so clearing out or reserving several books at once no longer means repeating the same action one at a time.
- Reworked "unreserve" into "edit reservation" everywhere a reservation can be changed (row icon, grid right-click menu, detail page, bulk bar): it now opens the existing reservation's details for editing (change who it's for, or remove it) instead of only offering a one-click release. Editing a bulk selection with mixed reservees prefills the name field blank rather than guessing.
- Fixed a bug where releasing a reservation only flagged it released instead of removing it, which left it permanently attached to its copy (via a one-reservation-per-copy database constraint) -- so the book's reservation banner never actually cleared, and reserving that same copy again for someone else always failed. Releasing now removes the reservation outright.


3.0.0 -- 2026-09-12
--------------------
- Added a Settings page that consolidates shelf management (rename/delete), member management (view roles, remove someone from the library), the invite link, and library deletion in one place, replacing the standalone Members page.
- Owners can now delete a library outright, from a danger-zone section that requires typing the library's exact name to confirm -- it permanently removes every shelf, book, and reservation in it for everyone with access.
- Owners/admins can remove a member from a library. The only safeguard: you can't remove a library's last remaining owner, so a library can never end up ownerless.
- Removing someone from a library, or deleting it outright, no longer strands their account -- if it leaves them with no library at all, the next time they sign in they see a screen inviting them to create their own, instead of being redirected to a confusing "please sign in" loop even though they're already signed in.

1.1.0 -- 2026-09-12
--------------------
- The reservation form now suggests previously-used names as you type (still lets you enter a new one), so the same person doesn't end up on the books under several slightly different spellings.
- The Library page shows every book in the collection, with shelf and reservation status, when the search box is left empty -- there was previously no way to see the whole collection at a glance, only shelf-by-shelf or via a matching search.
- A book whose ISBN lookup failed (e.g. a transient API hiccup) is now retried on the next scan instead of being stuck forever as "Unknown title" -- the first version cached any lookup result, success or failure, permanently.
- Widened the ISBN lookup's per-request timeout after finding a real title lookup was timing out in production specifically for books with unusually large catalog records (a full table of contents can be tens of KB), which a smaller local/dev timeout budget didn't surface.


1.0.0 -- 2026-09-12
--------------------
- Initial release: scan a book in or out of a library by ISBN, using a USB/Bluetooth barcode scanner (or typing the code) on desktop, or a phone's camera on mobile. Book details are looked up automatically from Google Books, with Open Library as a fallback for anything Google Books can't resolve.
- Organize books onto shelves, browse a shelf's contents, and search the whole library by title, author, or ISBN.
- Reserve a copy for a specific person and release the reservation later; scanning a reserved copy back out automatically marks the reservation fulfilled.
- Deployed on Vercel with a Postgres database on Neon.
